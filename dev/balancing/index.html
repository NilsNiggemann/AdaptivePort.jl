BalancingLearner

BalancingLearner serves several learners of the same kind with one runner and always asks the child whose next point promises the most (strategy = :loss_improvements, or :loss, :npoints, :cycle). Use it to sample a family of functions (different parameters, different signals) under a shared budget. Points are (index, point) with a 1-based child index, and balancer.f is a AdaptivePort.Dispatch that routes a point to its child's function.

using AdaptivePort

fs = [x -> x, x -> sin(3x), x -> tanh(50x), x -> sin(40x) * exp(-x^2)]
balancer = BalancingLearner([Learner1D(f; bounds = (-1, 1)) for f in fs])
BlockingRunner(balancer; max_npoints = 400, ntasks = 4)
npoints.(balancer.learners)    # the hard functions got most of the points

This is examples/balancing.jl. AdaptivePort.from_product builds the children from a parameter grid:

b = AdaptivePort.from_product((x; a, b) -> a * x + b, Learner1D, (bounds = (-1, 1),), (a = 1:3, b = [0.0, 1.0]))
  • Children must be the same type and have comparable losses; otherwise pick :npoints or :cycle.
  • Telling a child directly bypasses the balancer's caches: use tell!(balancer, (i, x), y).
  • result(balancer) is the vector of child results; to_table stacks the child tables with a learner_index column, and save_data writes the whole balancer to one file (Saving and export).
  • done(balancer) without tol works when the children have their own goal (for example SequenceLearner); then the runner stops when all are done.
