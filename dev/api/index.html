API reference

Docstrings of all exported and selected internal names. The docstrings of LearnerND, AverageLearner, AverageLearner1D, IntegratorLearner and SequenceLearner are at the end of their learner pages; everything else is here.

Learner interface

AdaptivePort — Module
AdaptivePort

Julia port of Python Adaptive: adaptive sampling of functions through an ask/tell! interface. Provides Learner1D (interval), Learner2D (rectangle) and LearnerND (box), all with scalar or vector values; AverageLearner and AverageLearner1D for noisy functions; IntegratorLearner (adaptive quadrature); SequenceLearner (a fixed list of inputs); and runners (BlockingRunner, AsyncRunner) that evaluate the function for you.

source
AdaptivePort.AbstractLearner — Type
AbstractLearner

Adaptive sampler of a function the caller evaluates: the learner proposes points, the caller evaluates them and reports back.

Interface

  • ask(learner, n; tell_pending = true): Vector of up to n new points, never ones already evaluated or pending.

  • tell!(learner, x, y): record the evaluation y = f(x...); returns learner.

  • tell_pending!(learner, x): mark x as issued but not evaluated; returns learner.

  • loss(learner): largest remaining loss, Inf until the learner covers its domain.

  • npoints(learner): number of evaluated points.

  • result(learner): copies of the evaluated data as a named tuple.

  • field f: the function, called by runners as f(x...) on a point x from ask.

  • pending_points(learner): Vector of the points issued but not yet told.

  • remove_unfinished!(learner): forget all pending points; returns learner. Runners call it whenever they stop.

  • loss(learner; real = true): real = false also counts the pending points as if they were evaluated.

  • AdaptivePort.ask_with_improvements(learner, n; tell_pending = true): (points, loss_improvements), upstream's return value of ask. Defining it gives ask for free.

  • to_table(learner): the evaluated data as a column table (named tuple of equal-length vectors), one row per tell!.

  • AdaptivePort.table_rows(learner, table): the (point, value) pairs that replay table through tell!.

Interface (optional)

  • done(learner; tol): defaults to loss(learner) <= tol.
  • AdaptivePort.has_own_goal(learner): true if done(learner) without tol is meaningful (the learner knows when it is finished); default false. Runners then stop on done(learner) when no tol is given.
  • AdaptivePort.load_table!(learner, table): tell every row of table (a to_table result); the default replays table_rows. Override when replaying in order is not enough (IntegratorLearner).

AdaptivePort.ask — Function
ask(learner, n; tell_pending = true)

Vector of up to n new points to evaluate, never ones already evaluated or pending (fewer, or none, once the learner has reached its resolution). With tell_pending = true the points are marked pending, so further calls do not return them again before they are told; false only peeks. Returns the points only; use AdaptivePort.ask_with_improvements for upstream's pair with the loss improvements.

AdaptivePort.tell! — Function
tell!(learner, x, y)

Record the evaluation y = f(x) and update the cached interval losses.

For vector output (vdim > 1) y is any iterable of length vdim; other lengths throw ArgumentError. Throws ArgumentError if x is outside the bounds (deviation: upstream stores but ignores such points). A repeated x is silently ignored and the first value is kept, as upstream; use update_value! internally to overwrite.

See Also

  • ask, tell_pending!
source
tell!(learner::Learner2D, (x, y), z)

Record the evaluation z = f(x, y); for vector output (vdim = M > 1) z is any iterable of length M, otherwise ArgumentError.

Throws ArgumentError if (x, y) is outside the bounds (deviation: upstream stores but ignores such points). Telling an evaluated point again overwrites its value, as upstream. Non-finite z (any non-finite component) is stored but left out of the triangulation.

source
tell!(learner::LearnerND, x, y)

Record the evaluation y = f(x...) at the point x (a tuple or vector of N coordinates); returns learner.

y is a number, or for vdim = M > 1 any iterable of M numbers. Throws ArgumentError if x is outside the bounds (deviation: upstream stores but ignores such points), if y has the wrong length, or if y is not finite (deviation: upstream does not check). Telling an evaluated point again is ignored, as upstream. The triangulation and the losses of the affected simplices are updated incrementally.

source
tell!(learner::AverageLearner1D, (seed, x), y)

Record the sample y = f(seed, x). A new x is inserted into the inner learner with y as its mean; a new seed at a known x updates the mean and error there; a known (seed, x) is ignored. Throws ArgumentError for x outside the bounds.

See Also

  • tell_pending!, result
source
tell!(learner::IntegratorLearner, x, y)

Record y = f(x) for a point x returned by ask, in any order. Intervals whose values are complete update the integral and error estimate. A non-finite y is allowed.

Throws

  • ArgumentError if x was not issued by the learner.
  • DivergentIntegralError if the integral appears to diverge.

Returns

  • learner.

AdaptivePort.tell_pending! — Function
tell_pending!(learner, x)

Mark x as issued but not yet evaluated, so ask does not hand it out again.

Throws ArgumentError if x is outside the bounds; a point that is already evaluated or pending is ignored.

tell_pending!(learner::LearnerND, x)

Mark the point x as issued but not evaluated; returns learner. If a triangulation exists, x subdivides the simplices that contain it in sub-triangulations that share the loss of the parent simplex by volume, so later ask calls avoid its neighbourhood.

Throws ArgumentError if x is outside the bounds (deviation: upstream ignores such points). Points that are already evaluated are ignored.

Mark point = (index, x) as pending in child index. Returns balancer.

AdaptivePort.loss — Function
loss(learner; real = true)

Current loss of learner: the largest interval priority, or Inf while a bound is not yet evaluated.

Intervals whose loss is NaN or infinite are ranked by their width instead, like upstream. With real = false pending points count as well (upstream loss(real=False)): the loss of an interval split by pending points is shared proportionally to the widths of its parts, a part without evaluated neighbour on both sides has loss Inf, and the result is Inf while a bound is neither evaluated nor pending or fewer than two points are known.

See Also

  • done, default_loss
source
loss(learner::Learner2D; real = true)

Largest per-triangle loss of the triangulation of the evaluated points, or Inf until all four corners are evaluated or while no triangle exists.

With real = false the pending points are triangulated too, with values interpolated from the evaluated data (upstream loss(real=False)), so the result is the loss the learner expects once the pending points are told.

See Also

  • done
source
loss(learner::LearnerND; real = true)

Largest simplex loss, Inf until the box corners are evaluated and a triangulation exists (deviation: upstream returns the loss of the first triangulation, however incomplete).

With real = false pending points count: the loss of a simplex that is subdivided by pending points is replaced by that of its largest part. Upstream's loss(real = False) is not implemented and returns the same as real = true.

source
loss(learner::AverageLearner; real = true)

Standard error of the mean in units of the tolerance (see AverageLearner). With real = false the pending samples count towards the sample size.

source
loss(learner::AverageLearner1D; real = true)

Loss of the means as for Learner1D; Inf until both bounds are told. With real = false pending points count as split points of their interval, as upstream, and an interval next to a pending point without a told neighbor has loss Inf.

source
loss(learner::IntegratorLearner; real = true)

Distance of the error estimate from the target, abs(abs(integral) * tol - error) as upstream. The pending points play no role, so real has no effect.

source
loss(learner::SequenceLearner; real = true)

Fraction of elements not told yet; with real = false, pending elements count as told.

source
loss(balancer::BalancingLearner; real = true)

Largest child loss; child losses are cached until the child is told or asked through the balancer.

Learners

AdaptivePort.Learner1D — Type
Learner1D{T, V, F, L}

Adaptive sampler of a scalar or vector-valued function on the interval bounds, driven by ask and tell!.

The value type V is T for scalar output (vdim = 1) and NTuple{vdim, T} for vector output. Vector values are scaled by one common y-scale, the largest per-component range, as upstream. Non-finite components are ignored when tracking the range.

Fields: f (stored for future runners, never called), bounds, loss_per_interval, dx_eps (smallest splittable interval width, 2 * max(abs.(bounds)) * eps(T) as upstream), xs/ys (evaluated points), losses (cached loss per interval), pending (points handed out by ask but not yet told), yrange (min and max of the finite told ys, per component for vector output) and yscale (the y-range at the last full recomputation of losses).

Invariants:

  • xs is strictly increasing, length(ys) == length(xs).
  • length(losses) == max(0, length(xs) - 1), losses[i] is the loss of the interval (xs[i], xs[i+1]), evaluated with the y-range current when it was last computed (as upstream, losses of untouched intervals are not refreshed until the range more than doubles); it is zero(T) if the width is below dx_eps.
  • maximum(yrange[2] .- yrange[1]) <= 2 * yscale once two finite distinct ys exist: as upstream, all losses are recomputed only when the y-range more than doubles, so that tell! stays O(1) in loss evaluations.
  • pending is strictly increasing and disjoint from xs.
  • All xs and pending lie inside bounds.

Construct with Learner1D(f; bounds).

See Also

  • ask, tell!, loss, default_loss
source
AdaptivePort.Learner2D — Type
Learner2D{T, V, F, L}

Adaptive sampler of a scalar or vector-valued function on the rectangle bounds = ((xmin, xmax), (ymin, ymax)), driven by ask and tell!.

Value type V is T for scalar output and NTuple{M, T} for vector output with M = vdim > 1. Fields: f (stored for future runners, never called), bounds, loss_per_triangle, points/values (evaluations in tell order), index (point → position in points) and pending (points handed out by ask but not yet told).

Invariants:

  • length(values) == length(points), index[points[i]] == i, points are distinct.
  • pending is disjoint from points.
  • All points and pending lie inside the closed rectangle bounds.

The learner works in scaled coordinates (p - center) / (xmax - xmin, ymax - ymin), which map the domain to [-1/2, 1/2]^2, as upstream. Triangulations are rebuilt from scratch when needed, nothing geometric is cached.

Construct with Learner2D(f; bounds).

See Also

  • ask, tell!, loss, triangles, default_loss

AdaptivePort.default_loss — Function
default_loss(xs, ys)

Loss of one interval: the length hypot(x2 - x1, y2 - y1) of the segment joining its endpoints, as upstream default_loss.

For vector values (a tuple of two NTuples) it is the maximum over the components of hypot(dx, abs(dy_i)), as upstream; a NaN component makes the loss NaN.

The learner passes scaled coordinates, x / (b - a) and y / yscale, so the loss is invariant under rescaling x or y. Measuring the graph's arc length makes steep regions dominate, while flat regions are still refined through the x term. A loss of the form dx * (1 + abs(dy)) was tried first and rejected: for small dx the dy term vanishes and the sampling becomes uniform.

Arguments

  • xs: the two scaled interval endpoints.
  • ys: the two scaled function values; for vector output two NTuples, scaled by the common y-scale.

Returns

  • The interval loss, same type as the inputs.

See Also

  • Learner1D
source
default_loss(points, values, triangles)

Per-triangle loss dev * sqrt(A) + 0.3 * A of upstream's 2D default_loss: A is the triangle area and dev the deviations estimate of the linear interpolation error.

The dev term refines where the function curves; the area term keeps refining flat regions so that no part of the domain is neglected. points are scaled to the unit square by the learner, so the loss is invariant under rescaling x, y or the values.

Arguments

  • points: scaled vertex coordinates, NTuple{2} each.
  • values: function values at points, Vector{T} or, for vector output, Vector{NTuple{M, T}} (losses are then summed over components, with values normalised by the largest component range, as upstream).
  • triangles: counter-clockwise index triples into points.

Returns

  • Vector of losses, one per triangle.

See Also

  • Learner2D
source
AdaptivePort.triangles — Function
triangles(learner::Learner2D)

Delaunay triangles of the evaluated points with finite values, as counter-clockwise index triples into result(learner).points.

The triangulation is computed in scaled coordinates (as the learner sees it), so it can differ from a Delaunay triangulation of the raw points when the domain is not square. Once the four corners are evaluated it covers the whole rectangle. Empty while fewer than three non-collinear points exist.

See Also

  • result, Learner2D

AdaptivePort.BalancingLearner — Type
BalancingLearner(learners; strategy = :loss_improvements, cdims = nothing)

Choose the points to evaluate from several learners of the same kind, so that a single runner serves all of them (port of upstream's BalancingLearner). The points are (index, point) with a 1-based index of the child (deviation from upstream's 0-based index), and learner.f is f(index, point), which calls the child's function. Children stay independently usable, but telling them directly bypasses the balancer's caches; use tell!(balancer, (i, x), y).

Their losses are compared, so all children must be the same kind (the same unparameterised type) and the losses must be comparable; if they are not, choose another strategy.

Keyword Arguments

  • strategy: :loss_improvements (default) picks the child whose next point promises the largest loss improvement, :loss the child with the largest loss (counting pending points), :npoints the child with the fewest points, :cycle goes through the children in turn. Ties go to the child with the fewest evaluated plus pending points. Children that are finished (done(child) for learners with an own goal) are skipped. The strategy is validated when set (balancer.strategy = :loss) and may be changed while running.
  • cdims: vector of named tuples labelling the children (default (i = 1,), (i = 2,), ...).

loss is the largest child loss, npoints the sum, result the vector of child results. done(balancer) without tol is available (and the runner stops on it) when the children have an own goal, and means that all are done. ask(...; tell_pending = false) leaves the children untouched (the points chosen meanwhile are made un-pending again, and the :cycle position is restored too). Exception: for an IntegratorLearner child, pending points that existed before the call are re-queued instead of kept pending, and the queue order may change.

Deviation: upstream invalidates only the real loss cache on tell_pending; here both cached losses are.

See Also

  • AdaptivePort.from_product
source

AdaptivePort.Runner — Type
Runner{L<:AbstractLearner}

Drives a learner: keeps up to ntasks evaluations of learner.f in flight (as f(x...): f(x) in 1D, f(x, y) in 2D), and asks the learner for a new point as soon as one finishes. Created by AsyncRunner or BlockingRunner; it starts on construction.

Fields: learner (inspect progress with npoints(runner.learner) and loss(runner.learner)), events (the channel the loop waits on), cancelled (set by cancel!) and task (the Task running the loop).

Type Parameters

  • L<:AbstractLearner: the learner type; the runner uses only the AbstractLearner interface.

See Also

  • status, cancel!, wait(runner)
source
AdaptivePort.BlockingRunner — Function
BlockingRunner(learner; kwargs...)

Same as AsyncRunner (same keywords), but return only once the runner has stopped. Rethrows an EvaluationError. At least one of tol, max_npoints, duration and end_time is required, as upstream refuses to block forever, unless the learner has its own stopping criterion (AverageLearner, IntegratorLearner, SequenceLearner).

Returns

  • The finished Runner.
source
AdaptivePort.AsyncRunner — Function
AsyncRunner(learner; tol = nothing, max_npoints = nothing, duration = nothing, end_time = nothing,
            executor = ThreadedExecutor(), ntasks = default_ntasks(executor),
            checkpoint = nothing, checkpoint_interval = 30)

Start learning learner.f in the background and return the Runner immediately.

The runner keeps ntasks evaluations in flight. Whenever results arrive it tells them to the learner, checks the goals, and asks for as many new points as there are free slots (with tell_pending = true), so a slow evaluation never holds back the others (upstream behaviour).

It stops when loss(learner) <= tol (without tol: when done(learner), for learners with their own stopping criterion), when npoints(learner) >= max_npoints, at the deadline, when ask returns no points and nothing is in flight (the learner is resolved to its numerical limit), after cancel!, or when an evaluation throws. On every stop, results that have already arrived are told, evaluations still running are abandoned (they cannot be interrupted; their results are dropped), and remove_unfinished!(learner) clears the pending points.

The loop runs in a task pinned to the caller's thread (@async) and is the only code that touches the learner, so the learner is mutated on the caller's thread at the caller's yield points (sleep, wait, I/O). Reading runner.learner from the calling task is safe without locks; reading it from another thread is not.

Keyword Arguments

  • tol: stop once loss(learner) <= tol (upstream loss_goal). nothing disables it.
  • max_npoints: stop once the learner holds this many points (upstream npoints_goal). npoints plus the evaluations in flight never exceeds it, so it is a hard limit on evaluations.
  • duration: stop this many seconds (a Real or a Dates.Period) after construction (upstream duration_goal).
  • end_time: stop at this Dates.DateTime (local time, as Dates.now(); upstream end_time_goal).
  • executor: where f runs; any callable executor(f, x) returning a fetch-able handle (see ThreadedExecutor, DistributedExecutor, DaggerExecutor, MPIExecutor).
  • ntasks: evaluations kept in flight. The default for ThreadedExecutor is 1, so f runs sequentially and need not be thread-safe; use ntasks = Threads.nthreads() for a threaded run.
  • checkpoint: a file path; the runner calls save_data(checkpoint, learner) every checkpoint_interval seconds and once more when it stops for any reason, including a failure.
  • checkpoint_interval: seconds between checkpoints.

Without tol, max_npoints, duration and end_time, the runner runs until cancel! or until ask returns nothing.

Returns

  • A running Runner. wait(runner) blocks until it stops and rethrows a failure.

Errors

  • If learner.f throws, results that already arrived are told and the runner fails with an EvaluationError holding the failed point. No retries.

See Also

  • BlockingRunner, status, cancel!

Executors

AdaptivePort.ThreadedExecutor — Type
ThreadedExecutor()

Evaluate on the threads of this Julia process: executor(f, x) is Threads.@spawn f(x...). The default executor of the runners. Start Julia with several threads (julia -t auto) and pass ntasks > 1 to evaluate concurrently.

default_ntasks(ThreadedExecutor()) == 1, so by default f runs one point at a time and need not be thread-safe.

See Also

  • AsyncRunner, DistributedExecutor, DaggerExecutor, MPIExecutor
source
AdaptivePort.DistributedExecutor — Type
DistributedExecutor(pool = CachingPool(workers()))

Evaluate on Distributed.jl worker processes: executor(f, x) is remotecall(f, pool, x...). Needs using Distributed (package extension). default_ntasks is the number of workers in pool.

f and everything it uses must be defined on the workers (@everywhere); only points and values travel. A CachingPool sends a closure to each worker once instead of on every call. An exception in f or a lost worker is reported as an EvaluationError (no retries).

See Also

  • AsyncRunner, ThreadedExecutor
source
AdaptivePort.DaggerExecutor — Type
DaggerExecutor(; options...)

Evaluate through Dagger.jl's scheduler, which spreads work over the threads and Distributed workers it knows: executor(f, x) is Dagger.spawn(f, options, x...). Needs using Dagger (package extension).

Keywords are passed to Dagger.Options (e.g. scope) and apply to every evaluation. default_ntasks is Dagger.num_processors(scope), the threads of all processes Dagger knows. Workers added after Dagger's scheduler started must be registered with Dagger.addprocs!(Dagger.Sch.eager_context(), workers()). Define f with @everywhere as a named function: an anonymous function is sent by value with every evaluation, and in the tests this intermittently failed on multi-threaded workers with a MethodError on the deserialized closure type.

AdaptivePort.MPIExecutor — Type
MPIExecutor(body, f; comm = MPI.COMM_WORLD, timeout = Inf)

Evaluate f on the ranks of an MPI job with native MPI.jl (package extension; needs using MPI and MPI.Init()). All ranks run the same script: rank 0 runs body(executor) (typically a runner), the other ranks serve f until rank 0 leaves body. Only points and values are sent; every rank holds f itself, and the executor rejects any other function. default_ntasks is the number of ranks minus one, so at least two ranks are needed.

Returns the value of body on rank 0 and nothing on the other ranks. Leaving body (normally or by an exception) stops every worker after its current evaluation; results of abandoned evaluations are received and dropped.

A worker that leaves early (exit in f, an error outside f) reports it, and its point fails. A rank killed by a signal is only noticed if mpiexec ends the job (MPI.jl's bundled MPICH does) or through timeout: an evaluation running longer than timeout seconds fails, and its rank gets no new points unless its result arrives later.

MPIExecutor(learner.f) do executor      # ranks > 0 serve f here and skip the block
    BlockingRunner(learner; tol = 1e-3, executor)
end

AdaptivePort.save_data — Function
save_data(path, learner)

Write the told data of learner to path; never the function, the learner struct or tasks. The extension picks the format: .csv is a header plus one row per point of to_table(learner) (numbers only, floats in shortest round-trip form so nothing is lost, readable by pandas and NumPy); any other extension (suggest .jls) is a Serialization file holding a named tuple with a format tag, a version number and the table.

The file is written to a temporary file next to path and then moved over it, so a reader or a crash never sees a half-written file.

Limits

  • Pending points are not saved.
  • Serialization files are tied to the Julia version, and loading one runs deserialize: only load your own files.
  • After load_data! the data are identical, but later sampling decisions can differ from an uninterrupted run where a learner's state depends on history (the lazy y-scale of Learner1D), as upstream.

Throws

  • ArgumentError for a .csv path if a column holds non-numbers; use a .jls path (for a DataSaver, which has a non-numeric extra_data column, or save saver.learner).

See Also

  • load_data!, to_table

AdaptivePort.load_data! — Function
load_data!(learner, path)

Fill a freshly constructed learner (the function is supplied by the constructor) with the data of a file written by save_data, by replaying tell!; returns learner. The format follows the extension as in save_data. To resume a run, use isfile(path) && load_data!(learner, path). The limits of save_data apply.

Throws

  • ArgumentError if the file does not exist, is not a file of this package, or its columns differ from those the learner expects (the message lists both).

AdaptivePort.deviations — Function
deviations(points, values, triangles)

Per-triangle estimate of the linear interpolation error, as upstream deviations: with values normalised by their range and gradients g from estimate_gradients, dev = sum_i max_j abs(v_i + g_i ⋅ (p_j - p_i) - v_j) over the vertices i, j of the triangle. For vector values (Vector{NTuple{M, T}}) all components are normalised by the largest component range, gradients are estimated per component and the deviations are summed over components.

source
AdaptivePort.estimate_gradients — Function
estimate_gradients(points, values, triangles; tol = 1e-6, maxiter = 400)

Gradient of the data at every point, a port of scipy's estimate_gradients_2d_global (used by upstream through CloughTocher2DInterpolator).

The gradients minimise the curvature of the piecewise-cubic Clough–Tocher interpolant along the triangulation edges (G. M. Nielson, Math. Comp. 40, 253 (1983); R. J. Renka & A. K. Cline, Rocky Mountain J. Math. 14, 223 (1984)), solved by Gauss–Seidel iteration until the largest relative change is below tol. Points without neighbours get a zero gradient.

source
AdaptivePort.choose_point_in_triangle — Function
choose_point_in_triangle(a, b, c; max_badness = 5)

New sample point in the triangle (a, b, c): the midpoint of its longest edge if the triangle is skinny, otherwise its centroid (upstream choose_point_in_triangle).

Badness is sqrt(3) / 4 * longest_edge^2 / area, 1 for an equilateral triangle; max_badness = 5 is upstream's value. Splitting the longest edge of skinny triangles keeps the triangulation from accumulating slivers.
