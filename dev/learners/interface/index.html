Common interface

All learners are subtypes of AbstractLearner and share one interface, so runners, saving and BalancingLearner work with any of them.

Basic functions

FunctionDoes
ask(learner, n)returns up to n new points and marks them pending
tell!(learner, x, y)records the value y at the point x
loss(learner)how much the sampling could still improve; smaller is better
done(learner; tol)loss(learner) <= tol
npoints(learner)number of evaluated points
result(learner)the data, as a named tuple of copies

The learner never calls the function. The caller evaluates it, or a runner calls learner.f(x...).

Pending points

ask hands out points and remembers them as pending until they are told. This is what lets several evaluations run at once without duplicates.

  • pending_points(learner) returns the points handed out by ask and not yet told.
  • tell_pending!(learner, x) marks a point as pending without ask, for points you chose yourself.
  • remove_unfinished!(learner) forgets the pending points, so ask can hand them out again. Call it after abandoned evaluations; runners do this when they stop.
  • loss(learner; real = false) counts pending points as if they were evaluated; real = true (default) uses told data only.
Pending points are not saved

save_data writes told points only. After a crash, the pending points are simply asked again.

Learners with their own goal

AverageLearner, IntegratorLearner and SequenceLearner know when they are finished (the mean is accurate enough, the integral converged, every element is told). For them done(learner) works without tol, and a runner without tol stops when they are done. A DataSaver follows its child, and a BalancingLearner whose children all have an own goal is done when all of them are. AdaptivePort.has_own_goal(learner) tells which learners do.

Advanced: implementing a learner

A new learner subtypes AbstractLearner, stores its function in a field f, and implements the methods in the Interface list of the AbstractLearner docstring: ask (or, more conveniently, AdaptivePort.ask_with_improvements, which gives ask for free), tell!, tell_pending!, loss, npoints, result, pending_points, remove_unfinished!, to_table and AdaptivePort.table_rows. Runners, saving and BalancingLearner then work unchanged. All learners of this package implement the full interface.

AdaptivePort.ask_with_improvements(learner, n) returns upstream's pair (points, loss_improvements); ask returns only the points.
